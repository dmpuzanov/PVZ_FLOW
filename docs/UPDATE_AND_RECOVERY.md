# PVZ.FLOW — обновление и восстановление

## Где хранятся данные

Единственный источник истины — файл `data\PVZ_FLOW_DATA.sqlite`.
Интерфейс не хранит операционные данные в браузере, поэтому очистка кэша
или переустановка браузера не приводит к потере данных.

## Резервные копии

Копии создаются в `data\backups`:

| Тип | Когда | Хранится |
|---|---|---|
| автоматическая | перед изменением данных | последние 30 |
| ручная | по кнопке в разделе «Настройки» | все |

Каждая копия — **один самодостаточный файл** `.sqlite`. Копия делается через
SQLite Backup API и сразу переводится в режим rollback-журнала, поэтому
рядом с ней нет файлов `-wal`/`-shm`, а сама копия открывается и
восстанавливается автономно.

### Сделать копию вручную

«Настройки» → «Создать резервную копию». Имя можно задать, чтобы затем
найти её в списке. Копия также получает метку `manual` и не удаляется
автоматически.

### Восстановить копию

«Настройки» → «Резервные копии» → выбрать файл → «Восстановить».

Восстановление требует явного подтверждения и:

1. создаёт страховочную копию текущего состояния,
2. заменяет рабочую базу выбранной копией,
3. переносит источник записей в журнал аудита как `restore`.

Восстановление отменяемых последствий не имеет — если после него что-то
пошло не так, возвращайте страховочную копию тем же способом.

## Ручное копирование файла

Если копируете `data\PVZ_FLOW_DATA.sqlite` вручную:

- закройте приложение сначала, иначе последние изменения остаются в
  `PVZ_FLOW_DATA.sqlite-wal` и не попадут в копию;
- копируйте **только** `.sqlite`. Файлы `-wal` и `-shm` в комплект не нужны.

## Синхронизация с Google Таблицей

Раздел «Синхронизация» → «Загрузить из Google».

### Матрица ПВЗ (ежедневные выбытия)

- Строки таблицы с датой **до 07.09.2026** (дата начала журнала в настройках)
  полностью игнорируются: журнал ещё не вёлся.
- **07–27.09.2026** — принятая базовая история: она считается уже
  синхронизированной по каждой паре дата/артикул, расхождения отмечаются как
  заблокированные базовой историей, но в базу не добавляются.
- С **28.09.2026** учитываются все локальные отгрузки независимо от источника
  (`google`, ручные, пустой источник), и в базу добавляется только
  положительная разница — фактически новые данные текущих дней.
- Синхронизация **добавляет** строки и никогда не удаляет их: если Google
  уменьшил количество, локальные строки остаются как были.
- Пробный запуск (dry run) ничего не пишет и возвращает план
  `plannedUnits` — сколько единиц будет добавлено.

### Таблица селлера (сверка)

- Синхронизация **добавляет** строки в базу и никогда не удаляет их.
- Идентификатор строки — `WB-GI-…`. Строка, уже зарегистрированная вручную,
  не импортируется повторно и не превращается в дубль.
- Полная выгрузка (все строки листа) запускается только вручную;
  по умолчанию загружаются изменения с последней метки времени.
- Строки без `WB-GI` и строки с неоднозначным дублем не импортируются:
  они попадают в отчёт о расхождениях.

### Неизменяемые строки

Строка, созданная синхронизацией, помечается источником `google`
и **не редактируется и не удаляется** через интерфейс. Это гарантирует,
что исходная таблица остаётся эталоном. Источник задаёт только сервер:
подделать его из браузера нельзя.

Чтобы исправить такую строку, удалите её из Google Таблицы и запустите
синхронизацию заново.

## Если приложение не запускается

| Сообщение | Причина и что делать |
|---|---|
| `Не найден runtime\node.exe` | распакован не весь архив |
| `Не найдена собранная часть интерфейса app\dist` | распакован не весь архив |
| `Сервер не сообщил о запуске за 30 секунд` | смотрите сообщения выше в этом же окне |
| порт занят | приложение само перейдёт на свободный порт и напечатает новый адрес |

Проверить целостность установленной базы можно так: остановите приложение,
скопируйте `PVZ_FLOW_DATA.sqlite` в отдельную папку и откройте копию
в любом SQLite-инструменте, выполнив `PRAGMA integrity_check`.
Должно вернуться `ok`.

## Обновление версии

1. Закройте приложение.
2. Сделайте резервную копию `data\`.
3. Распакуйте новую версию поверх старой, **не удаляя** папку `data`.
4. Запустите `START_PVZ_FLOW.cmd`.

Структура базы обновляется автоматически при первом запуске: сервер
применяет недостающие миграции в транзакции и проверяет целостность после
каждой из них. Данные при миграции не изменяются, кроме пересоздания
служебных триггеров.
